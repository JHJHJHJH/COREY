## Production Build

```bash
pnpm build
pnpm start
```

The build uses `next build --webpack` and generates Fumadocs source files before
building.

## Docker

Build the runner image:

```bash
docker build --target runner -t corey:local .
docker build --target mcp-stdio-runner -t corey-mcp:local .
```

Run the image with backend environment variables:

```bash
docker run --rm -p 4000:4000 \
  -e DATABASE_URL="postgresql://corey:corey@host.docker.internal:5432/corey?schema=public" \
  -e S3_ENDPOINT="http://host.docker.internal:9000" \
  -e S3_REGION="ap-southeast-1" \
  -e S3_ACCESS_KEY="corey" \
  -e S3_SECRET_KEY="corey-secret" \
  -e S3_BUCKET="corey-models" \
  corey:local
```

For a local-first deployment without server model storage, provide
`DATABASE_URL` only. `/api/health` will still return `status: "ok"` with
`modelStorageAvailable: false`; the viewer continues to load local IFC files
from the browser, while server-backed upload/download is disabled.

## Docker Compose

For the app plus local Postgres and MinIO:

```bash
docker compose --env-file .env -f docker/docker-compose.deploy.yml up --build
```

The app healthcheck calls `/api/health`.

The MCP companion is intentionally not a Compose service: the MCP client owns
its stdio lifecycle and starts it with `docker run -i`. Set
`COREY_MCP_BRIDGE_URL` and `COREY_MCP_BRIDGE_SECRET` on the app, then pass the
same secret plus `COREY_BASE_URL` and `COREY_MCP_ALLOWED_ORIGINS` to the
companion. See [MCP Companion](/docs/mcp).

## Release Checklist

```bash
pnpm verify
docker compose --env-file .env -f docker/docker-compose.deploy.yml build app
docker build --target mcp-stdio-runner -t corey-mcp:local .
```

Version tags publish `corey` and `corey-mcp` GHCR images through the release
workflow.
